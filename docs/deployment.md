# Deployment operations

Build with npm ci --ignore-scripts, prisma:generate, and build. Native production runs dist/src/main.js. Docker builds dependencies, generated client and compiled output in separate stages, then uses a non-root runtime user with read-only filesystem, dropped capabilities, init/signal handling, no-new-privileges and bounded memory/CPU. .env never enters the image. The migration image contains tooling but is not the public API runtime.

Before production set NODE_ENV=production, HTTPS application/CORS URLs, COOKIE_SECURE=true, SWAGGER_ENABLED=false, independently random secrets, and DATABASE_TLS=true. Provide a valid trusted PostgreSQL certificate chain and DATABASE_CA_FILE if necessary. Configure HTTPS at the reverse proxy, explicitly trusted proxy CIDRs, body/request timeouts, backups, monitoring and a private network. The local Compose database does not automatically configure TLS certificates: provide a secured database configuration or managed/private PostgreSQL before enabling production mode. Localhost port bindings are intentional.

Run a single controlled migration job before updating API replicas. Runtime containers receive no admin or migration credentials. Backup before schema changes and test migration on a restored copy. Release application changes only when readiness succeeds. /health/live checks process state; /health/ready checks the database and returns minimal results. Finite query/connect timeouts avoid indefinite readiness waits. Graceful shutdown closes the shared Prisma pool; upstream load balancers must drain requests before termination.

PostgreSQL volume deletion is never a normal stop operation. Encrypt backups, restrict access, define recovery point/time objectives, enable point-in-time recovery when needed, and periodically prove restoration. Application rollback does not reverse schema migrations; prefer backward-compatible rollout and forward repair. First-start Compose role initialization does not update existing role passwords; rotate database roles explicitly, then update runtime secrets. Rotate SESSION_SECRET to invalidate all sessions with a deliberate customer reauthentication plan.

Keep logs structured with no sensitive payloads. Metrics/tracing should measure latency, errors, pool saturation and authentication capacity without personal labels. Horizontal scaling requires shared rate limiting and review of database pool totals; persistent sessions already survive API restarts. No paid provider, Kubernetes or external queue is required. GitHub Actions uses disposable secrets and PostgreSQL, never production data; deployment and remote publication are not automatically configured.
