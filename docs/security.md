# Security assumptions

Opaque 32-byte session cookies are HMAC-digested with SESSION_SECRET before database storage. Raw identifiers never appear in JSON or logs. Argon2id uses a minimum of 19 MiB, time cost 2 and parallelism 1, configurable with bounded concurrent work. Missing users take a dummy-hash verification path. Duplicate signup has the same response and hashing path. Signin rotates the presented prior session; signout removes it. Absolute expiry is enforced on every lookup. Expired records are removed during later signins; schedule a maintenance deletion for inactive users to bound long-term storage. Secret rotation invalidates all sessions; deliberate global invalidation is required when rotating.

Every route is protected unless explicitly marked public. Authenticated owners come from server context, never request bodies. Read/update/archive and cursor queries include ownership. The prototype account API never exposes password hashes, session digests or ownership internals. Idempotency is database-enforced per owner. Archived financial records are retained; legal retention rules must be defined before real customer data.

Mutations require exact allowlisted origins and authenticated mutations require a session-bound HMAC CSRF token. Cookies are HttpOnly and secure in production. Deploy frontend/API under the same site where possible; cross-site deployments require SameSite none plus HTTPS and must account for browser third-party-cookie restrictions. No JWT/localStorage credentials. CORS is explicit with credentials and never wildcard.

Helmet, body limits, strict DTOs, correlation IDs, no-store, SQL parameterization, default-deny sessions, bounded hashing and rate limits are active. TRUST_PROXY_CIDRS defaults empty; only list actual reverse-proxy networks, never /0. Atomic Redis-backed throttling applies stricter authentication limits across replicas and fails closed during Redis outages. IPv6/proxy topology and abuse limits should be tested against the intended hosting environment.

Winston request serializers log only request id/method and status/duration; no bodies, URL queries, cookies, passwords, auth/CSRF headers or financial values. Audit events record authentication outcome without email/password. Production config rejects insecure cookies, non-HTTPS origins, unverified DB connections and public Swagger. Session secret, passwords and CA files are runtime-injected and excluded from image contexts.

Password reset, email verification and MFA intentionally have no implementations without delivery/identity providers. Add a provider interface when selected; reset tokens must be hashed, expiring, single-use, atomic, and invalidate sessions. Do not invent delivered email success. Credential-based signup without verification is an initial foundation limitation; gate SIGNUP_ENABLED before opening public onboarding. No payment processing or compliance certification is claimed. Audit dependencies in CI and review supported updates before deployment.

Prisma's transitive dependencies are pinned through narrow npm overrides to deepmerge-ts 8.0.2 and mysql2 3.24.6. These resolve the published [DeepmergeTS advisory](https://github.com/advisories/GHSA-ggr8-5vv4-36mx) and [MySQL2 authentication](https://github.com/advisories/GHSA-3f6p-5ww8-9rcr) and [compression](https://github.com/advisories/GHSA-rgwj-5xj2-c3m3) advisories without downgrading Prisma. Schema generation, migration deployment, and tests verify the actual PostgreSQL path. Reassess the overrides when updating Prisma.
