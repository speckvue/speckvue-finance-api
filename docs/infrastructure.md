# Logging and Redis

Winston emits timestamped JSON logs to stdout and daily rotating application/error files. LOG_LEVEL, LOG_DIRECTORY, LOG_FILE_ENABLED, LOG_MAX_SIZE (default 20m), and LOG_MAX_FILES (default 14d) control output. Rotated archives are compressed; transport audit files manage retention. Keep the log directory private. Docker uses a writable named log volume alongside the read-only application filesystem. Logs and audit files are excluded from Git and image build contexts. Metadata is allowlisted: no request bodies, credentials, cookies, email addresses, or financial values. Use fixed event messages, not raw error messages or user input. Backend shutdown drains transport streams before exit.

Redis connection fields are REDIS_HOST, REDIS_PORT, REDIS_PASSWORD, REDIS_DATABASE, REDIS_KEY_PREFIX, REDIS_TLS, REDIS_CONNECT_TIMEOUT_MS, and REDIS_COMMAND_TIMEOUT_MS. Docker maps the client host/port through DOCKER_REDIS_HOST/REDIS_INTERNAL_PORT. API Redis binds to localhost:6379; web Redis binds to localhost:6380. Each repo has its own password and key namespace; the repos run independently. The initializer creates random passwords without printing them. Runtime credentials are not build arguments or baked into images.

The Docker Redis service runs as the redis user with authentication, bounded memory, noeviction, and no persistence. It is a disposable cache/coordination store; durable records and sessions remain in PostgreSQL. Redis restart clears short-lived counters/cache. Production requires private networking, verified TLS, access restrictions, and monitoring for memory pressure. Backend production validation requires REDIS_TLS=true. Local Redis uses plaintext only inside the local development network.

Backend rate limiting uses atomic Lua counters with TTL and block expiry shared across replicas. Keys hash request identity rather than storing IP addresses. Redis failure returns 503 rather than bypassing abuse protection. Readiness checks PostgreSQL and Redis. Liveness is process-only. The Redis service also provides explicit expiring cache operations; it does not cache financial records or authenticated responses.

Frontend Redis runs only in Node server modules, never browser/Edge code. /api/health checks Redis readiness. /api/backend-status caches the public backend readiness result for REDIS_CACHE_TTL_SECONDS (default 5) using API_INTERNAL_URL. Cached values are schema-validated. Redis cache failure falls back to the origin; private data is never stored by this helper. Browser responses use no-store. In Docker, DOCKER_API_INTERNAL_URL targets the API through host.docker.internal; set an appropriate private service URL in deployment. Backend status remains unavailable if the API is stopped.

Start infrastructure with npm run infra:up (API) or Docker Compose for the web repo, then run the native application. Full Docker and Watch include Redis automatically. Use npm run docker:up, npm run docker:watch, and npm run docker:down as appropriate. The frontend docker:prod selects the compiled production image. Stop commands preserve PostgreSQL and log volumes.

If your build network requires a proxy, set DOCKER_HTTP_PROXY, DOCKER_HTTPS_PROXY, and DOCKER_NO_PROXY in .env. Compose passes Docker predefined proxy build arguments, which are excluded from image history/configuration unless explicitly declared in a Dockerfile. Leave them blank for direct networks and CI. Never declare proxy values as runtime ENV or NEXT_PUBLIC_* settings.

Redis command deadlines use AbortSignal; they do not impose an idle socket timeout. Connections can remain open between requests. Reconnect attempts are bounded per attempt, and later requests can recover a closed connection. Application shutdown closes Redis before draining Winston.
