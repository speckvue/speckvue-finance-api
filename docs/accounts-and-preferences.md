# Accounts, onboarding and preferences

Email/password signup and signin use the API's Argon2id password hashes and opaque HttpOnly sessions. Duplicate signup returns the same generic acknowledgement without changing an existing account. No SMTP service, email verification or forgotten-password delivery is configured. Email addresses are identifiers and are not treated as verified addresses. Password changes require the current password and invalidate all sessions. A credential version check also rejects sessions created concurrently from obsolete credentials.

The frontend exposes /signup, /signin, /onboarding, /workspace and /settings. Server checks run at each private page boundary and in the account layout. Unauthenticated users go to signin; accounts without completed onboarding go to onboarding. There are no demo sessions or client-side authorization shortcuts.

The browser calls the allowlisted same-origin /api/backend gateway. API_INTERNAL_URL is server-only; Docker uses DOCKER_API_INTERNAL_URL. API_BASE_PATH must match the API prefix/version, and SESSION_COOKIE_NAME must match the backend. The gateway forwards only the session cookie, an exact validated Origin and CSRF header, bounds JSON request bodies to 16 KiB, disables caching and normalizes the browser cookie path to /. The backend validates sessions, origins, CSRF, DTOs and ownership independently. Never expose the private API origin as a browser credential source.

Onboarding stores display name, ISO currency, supported formatting locale, IANA timezone, light/dark/system appearance and first day of week. Explicit device detection fills language/timezone only after the user requests it. The interface remains English; locale controls formatting. Initial defaults are USD, en-US, UTC and Monday and remain editable before confirmation. Changes persist in PostgreSQL and are validated on the server. The first onboarding timestamp is preserved when a request is retried. Appearance uses next-themes, with account settings saved through the API.

GET /users/me returns the safe profile and preferences. POST /users/me/onboarding completes first-time setup; PATCH /users/me/preferences updates the complete preference object. Both mutations require a verified session, Origin and CSRF. GET /auth/sessions lists up to 100 active owned sessions with creation/expiry timestamps and the current-session marker. DELETE /auth/sessions/:id revokes an owned session. POST /auth/signout-all invalidates all sessions. POST /auth/password accepts currentPassword and newPassword and signs every device out on success. Passwords, tokens and preference values are excluded from audit log metadata.

## Verification

API unit/integration tests cover origin/CSRF enforcement, safe profile responses, onboarding validation, user isolation, session ownership/revocation, password changes and invalidation. Frontend unit tests cover real form submission and safe gateway behavior. Browser tests cover anonymous redirects and, when E2E_AUTH_ENABLED=true, the connected signup-to-onboarding-to-settings-to-signout journey.

For connected tests, build both repositories, start the web Redis service, free the frontend APP_PORT, and run npm run test:browser in the API repository. E2E_API_PORT in the API .env selects the temporary API port. The runner starts disposable PostgreSQL and Redis, migrates them, launches the compiled isolated API and runs frontend Playwright tests. Test accounts are discarded with the owned database container. It requires the two repositories to remain sibling folders. Standalone frontend CI skips connected cases unless explicitly enabled; API tests continue to run independently.

Before a public launch, configure verified email delivery/recovery, production TLS and trusted ingress/rate-limit topology. The backend currently sees gateway traffic from the web server's address, so its network limits apply to that shared address. Configure and verify a trusted reverse proxy before relying on client-IP limits across public traffic. These deployment tasks do not require SMTP credentials to be stored in this scaffold.
